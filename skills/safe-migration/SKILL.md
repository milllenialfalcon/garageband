# Safe migration

Code mistakes are fixed with a revert. Data mistakes may be permanent. Migrations get the most care in the whole factory.

## Rules
- Every schema change is generated by the migration tool (Drizzle, Prisma, Supabase, etc.) and committed. Never edit production schema by hand.
- Never run destructive commands (drop, truncate, reset) against a shared database from an agent session.
- A migration and the code that depends on it ship in **separate** PRs when the change isn't purely additive.

## Expand → migrate → contract
1. **Expand** (safe, additive): add the new column/table, nullable or with a default. Old code keeps working. Ship it.
2. **Migrate**: code writes to both old and new; backfill existing rows in batches (idempotent, resumable, logged). Ship it. Verify counts match.
3. **Switch**: code reads from the new structure. Ship it. Watch it (watch-after-ship).
4. **Contract**: only after a full release cycle without problems, remove the old column/table. Ship it.
Renames are done as add new + copy + switch + remove old. Never a direct rename on live data.

## Before running anywhere but local
- [ ] Migration applied and rolled back successfully on a fresh local or preview database.
- [ ] Rollback script exists and is tested (or a written reason why the step is irreversible, which makes it a one-way door).
- [ ] Backup taken (or point-in-time recovery confirmed) immediately before running on staging and production; note the restore point.
- [ ] Large tables: estimate lock time; batch backfills; avoid locking writes during busy hours.
- [ ] Row-level security / permission rules updated and tested for the new structure.
- [ ] Personal data: new fields marked in the architecture plan; retention and deletion considered.

## Founder Call
Send a decision-brief before staging and production: what changes in plain English, data affected, risk, rollback, backup restore point, and best time to run. Run only after an explicit yes.

## After
Verify row counts and spot-check records. Log the migration in the PR summary and the decision log.
